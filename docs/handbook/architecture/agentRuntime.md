# Agent Runtime 아키텍처

Agent Runtime의 정본은 `src/dartlab/ai/runtime/`이다. 공급자별 모델 API 통합 대신 설치형 CLI 프로토콜을 어댑터로 두고, DartLab 계약과 품질 판정은 런타임 공통 계층이 소유한다.

## 경계

```text
manifest와 discovery
  -> 준비 상태와 기본 런타임 선택
  -> 네이티브 CLI driver와 session binding
  -> 읽기 전용 DartLab MCP
  -> 정규화 AgentEvent
  -> answer quality와 evidence commit
  -> public Agent event gateway
  -> CLI와 local GUI
```

- `manifests/*.toml`은 실행 파일 후보, 버전 확인, 인증 확인, 로그인 명령, 프로토콜 지원 여부를 선언한다.
- `registry.py`와 `discovery.py`는 매니페스트를 읽어 설치와 인증 상태를 판정한다. 인증 명령의 원문 출력은 공개 상태에 포함하지 않는다.
- `engine.py`는 기본 런타임 선택, 대화와 네이티브 세션 결속, 취소, 재개, 근거 수집을 소유한다.
- driver는 Codex app server, Claude stream JSON, ACP 차이를 `AgentEvent`로 정규화한다.
- `analysisCapsule.py`는 질문에서 대상, 지표, 기간을 분해한 `claimCellContract`를 application context에 넣는다. 최초 턴과 교정 턴은 같은 원 질문 계약을 사용한다.
- `agent.py`는 품질 판정을 답을 삭제하는 게이트가 아니라 사용자에게 보이는 검증 뱃지로 쓴다. 실측(2026-08-04 분석 배터리)에서 게이트 시절 8 질문 중 6 건이 인용 서식 사유로 기각됐고, 기각된 답들도 근거를 8~56 개 실제로 인용한 실분석이었다. 우리는 모델 루프를 소유하지 않으므로 답을 다시 쓰게 만들 수 없고, 자동 repair 재주입도 하지 않는다.
- 검증 결과는 `verified`, `unverified`, `failed` 세 상태다. 근거 계약을 못 채운 답은 미검증 뱃지와 함께 전달하고, 런타임 자체가 실패한 경우만 실패로 남긴다. 턴이 상한을 넘겨 끝나지 않아도 그때까지 쓴 본문과 근거는 미완 표시와 함께 전달한다.
- 런타임이 말한 실패 사유는 그대로 사용자에게 보인다. 사유를 품질 라벨로 갈아 끼우면 무엇을 해야 할지 알 수 없는 문장만 남는다.
- `agentGateway.py`는 공개 이벤트 allowlist만 SSE로 투영한다. 실행마다 `RUN_ERROR`는 최대 한 번, `RUN_FINISHED`는 정확히 한 번 발행한다.

## 도구와 권한

설치형 에이전트에는 `agent` MCP profile만 연결한다. 이 profile은 Skill OS 조회와 정식 엔진 읽기 호출만 광고한다. 임의 Python 실행, 파일 저장, 데이터 변경 도구는 광고하지 않는다. Claude driver는 명시적 허용 목록과 함께 내장 실행 도구를 이름으로 차단한다. 허용 목록만 두면 차단이 되지 않는다는 것을 실측으로 확인했다.

도구 검색은 막지 않는다. 지연 로딩되는 DartLab 도구를 그 경로로 발견하기 때문에, 막으면 도구 사용이 0 이 된다. 이것도 실측으로 확인한 뒤 되돌린 것이다.

에이전트에게 건네는 표면은 셋뿐이다. MCP instructions, tools/list 의 도구 설명과 스키마, 런타임이 주입하는 분석 캡슐. 셋 중 어느 하나라도 광고 목록에 없는 도구를 가르치면 에이전트는 존재하지 않는 도구의 사용법을 배운다. 그래서 지침은 손으로 적지 않고 광고 SSOT 에서 생성하며, `tests/mcp/test_brokerSurfaceCoherence.py` 가 세 표면 모두를 프로필별로 검사한다.

MCP payload 예산의 기준은 우리가 감당할 크기가 아니라 소비하는 CLI 가 받아 주는 크기다. 예산이 소비자 상한보다 크면 초과분이 잘리는 게 아니라 결과 전체가 폐기되고 근거까지 함께 사라진다. 축약이 필요할 때도 본문을 먼저 줄이고 근거 목록은 끝까지 비우지 않는다.

설치와 MCP 연결은 명령 배열과 digest를 먼저 제시한 뒤 정확한 digest 승인에서만 실행한다. shell 문자열을 조립하지 않는다. 로그인은 공식 CLI 명령을 사용자에게 제시한다.

## 근거 무결성

`EngineCall` 결과는 canonical tool name, tool call ID, source identity, 기간과 값을 보존한다. 연간 손익과 현금흐름은 분기 합계, 연간 재무상태는 4분기 말 snapshot으로 만든다. 로컬 계산 결과는 canonical upstream lineage가 있을 때만 최종 근거로 인정한다.

근거 계약을 못 채운 답의 근거는 candidate로 격리해 표시한다. 답변이 실제로 인용한 근거와 수집만 하고 쓰지 않은 근거를 화면에서 구분한다.

## 근거를 판단 가능한 형태로 건네기

우리는 모델 루프를 소유하지 않는다. 그래서 답변 품질을 올리는 정공법은 답을 고쳐 쓰는 것이 아니라 **건네주는 근거 자체를 판단 가능한 형태로 만드는 것**이다. 지침을 더 쓰는 것은 이미 실패한 방법이다. 지침이 안 지켜지는 이유는 대개 데이터가 그것을 불가능하거나 비싸게 만들기 때문이다.

실측 사례 셋이 같은 결론을 가리킨다. 스크리닝이 도구를 56 회 부르던 것은 지침 불이행이 아니라 `scan` 이 행 본문 없이 개수만 돌려줘서 종목마다 다시 부를 수밖에 없던 것이다. 비교 기준이 답변에 없던 것은 캡슐이 덜 요구해서가 아니라 이미 계산된 신용 등급과 산업 국면이 payload 안에만 있고 본문에 없어서다. 판단이 바뀌는 조건이 빠지던 것은 반사실 추론이 어려워서인데, 관측된 마진을 주면 그 자리에서 산술이 된다.

`ai/tools/panelInsight/` 가 이 원칙의 구현이다. 값을 꺼내는 원시 도구(`values`), 표에서 계산되는 파생 지표(`derived`), 회사 밖 기준과 뒤집히는 지점(`anchors`) 셋으로 나뉜다. 손에 이미 있는 시계열만 써서 파생 지표, 이익 변동 요인 분해, 기간 내 위치와 기저효과, 관측 범위 기준 하방 산술, 회사 위치를 본문에 함께 싣는다. 추가 조회가 없으므로 지연이 늘지 않는다.

이 원칙은 한 도구에만 적용하면 그 도구를 쓰지 않는 질문에서 통째로 빠진다. 실측(2026-08-06) 에서 `Company.panel` 은 본문 1810 자를 건네는데 정작 판정을 내는 `analysis` 와 `quant` 와 `credit` 은 본문이 0 자였다. 요약은 "실행 완료" 다섯 글자였고 내용은 9184 자짜리 중첩 dict 였다. 같은 배터리에서 panel 경로 답변은 근거 39 건, analysis 경로 답변은 3226 자를 쓰고도 근거 3 건에 인용 2 건이었다. 답에 적힌 수치가 맞는데도 확인할 방법이 없었다.

`engineResult.py` 가 그 구멍을 막는다. 기간별 행 목록, 기간을 키로 쓴 맵, 최상위 스칼라, 격자 미리보기 네 모양을 받아 표와 줄로 편다. 계산도 해석도 하지 않고 옮겨 적기만 한다. 표를 그리면 그 표를 가리키는 근거를 함께 발급하고, **표 제목 옆에 그 근거 id 를 적는다.** 가리킬 이름이 본문에 없으면 인용은 비싼 일이 되고 실제로 안 된다.

효과는 형식이 아니라 내용에서 나왔다. 표로 펴 준 뒤 모델이 우리 데이터를 감사하기 시작했다. 어떤 블록의 2026 년 행이 연도 미완결로 생긴 계산 아티팩트라는 것, 유효세율이 여러 해 내내 정확히 같은 값으로 찍혀 있어 기본 가정값이라는 것을 스스로 짚었다. 중첩 dict 안에서는 보이지 않던 것들이다. **못 재는 것을 못 잰다고 적는 것**도 같은 일을 한다. `assessmentStatus partial` 을 본문에 실었더니 모델이 그것으로 자기 확신의 범위를 스스로 좁혔다.

비교 기준은 질문의 결을 따라가야 한다. 실측(2026-08-06) 에서 재무 건전성을 물은 질문이 업종 기준을 하나도 못 받고 끝났다. 모델이 안 쓴 것이 아니라 쓸 것이 없었다. 그때 붙던 업종 축은 영업이익률과 ROE 와 매출 성장률뿐이라 "부채비율 30% 가 높은 건가" 에 답할 재료가 아예 없었다. 그래서 부채비율과 유동비율을 축으로 더했다. 방향이 다른 축은 방향을 문장에 적는다. 부채비율을 "업종 상위 몇 %" 로 쓰면 정확히 반대로 읽힌다.

비용이 드는 재료는 **임계 경로에서 순차로 재는 쪽**이 배경 예열보다 빠를 수 있다. 업종 표를 재무제표 조회와 동시에 읽게 했더니 69.2 초가 걸렸고, 예열을 없애고 조회가 끝난 뒤 순차로 재게 했더니 44.4 초였다. 둘 다 같은 저장소를 읽는 작업이라 병렬이 서로를 느리게 만든 것이다. 동시성은 공짜가 아니고, 예열은 겨루는 상대가 없을 때만 이득이다.

시장 횡단면 표는 회사가 아니라 시장에 속한다. 회사를 물을 때마다 다시 읽을 이유가 없으므로 프로세스 안에 한 번만 읽어 둔다(`industry/calcs/sectorTables.py`). 단 원본 격자를 들고 있지는 않는다. 필요한 열만 실수로 뽑아 3MB 로 줄이고 원본은 놓는다. 압력 관리 캐시에 수천 행 격자를 넣으면 이 저장소의 메모리 압력에서는 곧바로 되돌려져, 예열해 놓고도 다음 호출이 처음부터 다시 읽는다.

지켜야 할 선은 하나다. **사실만 적고 판정하지 않는다.** 완만한 시계열에 기저효과 경고를 붙이지 않고, 조합표에 없는 현금흐름 모양에는 해석을 지어내지 않으며, 하방 산술은 임의 시나리오가 아니라 실제 관측치만 쓰고 전망이 아님을 문장에 명시한다. 없는 문제를 만들거나 모르는 것을 아는 척하면 근거 제품의 신뢰가 무너진다.

`Panel` wide 격자의 형태와 내용은 건드리지 않는다. 여기서 만드는 것은 표현 계층의 병존 projection 이다.
Python ask와 CLI는 실패 `done`을 빈 문자열이나 종료코드 0으로 낮추지 않는다.
