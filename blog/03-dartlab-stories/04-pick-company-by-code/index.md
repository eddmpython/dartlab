## 회사 이름보다 먼저 코드가 필요하다

투자자는 보통 회사 이름으로 생각한다. 삼성전자, SK하이닉스, NAVER처럼 말이다. 그런데 데이터 도구는 이름보다 코드를 더 좋아한다. 이름은 바뀔 수 있고, 띄어쓰기와 약칭이 흔들리며, 같은 이름처럼 보이는 계열사도 많다. 코드는 훨씬 덜 흔들린다.

dartlab 브라우저 글에서 회사를 여는 기본 입력은 여섯 자리 숫자다. 삼성전자는 `005930`, SK하이닉스는 `000660`, NAVER는 `035420`이다. 이 번호를 넣으면 dartlab은 국내 회사로 보고 [DART](https://dart.fss.or.kr/) 공시 데이터로 간다.

```python
import dartlab

c = dartlab.Company("005930")
c.market
```

`KR`이 나오면 국내 공시 경로가 열린 것이다. 지난 편 [공시 코드셀, 실행 순서](/blog/how-notebook-runs)에서 배운 것처럼, 이제 `c`라는 이름은 아래 셀들이 계속 쓸 수 있다.

![회사명에서 코드로, 코드에서 Company로 이어지는 길](./assets/dartlab-story-04-code-route.webp)

여기서 중요한 것은 `Company`가 투자 의견을 내는 버튼이 아니라는 점이다. `Company`는 분석 대상의 주소를 잡는 첫 손잡이다. 이 손잡이를 잘못 잡으면 뒤에서 아무리 멋진 표를 열어도 다른 회사를 보고 있게 된다.

## 왜 브라우저에서는 이름 검색을 막아 두었나

로컬 설치본에서는 회사 이름으로 찾는 편의 기능을 붙일 수 있다. 하지만 이 브라우저 글에서는 이름을 코드로 되돌리는 과정을 자동으로 처리하지 않는다. 이것은 불편해서가 아니라 의도적인 경계다.

브라우저는 외부 사이트에 아무 요청이나 보낼 수 없다. 코드와 회사명을 잇는 전체 표를 새로 받거나, 거래소 검색을 실시간으로 긁어 오는 일은 보안 정책과 데이터 제공 조건에 막힌다. 그래서 이 글의 실행 셀은 **이미 알고 있는 코드**를 넣는 방식으로만 구성한다. 이름 검색은 로컬에서만 됩니다.

대신 독자는 코드가 무엇을 뜻하는지 더 분명히 배운다. 코드는 회사의 별명이 아니라 데이터 주소다. DART 공시, 재무제표 격자, 나중에 볼 스캔 결과가 모두 이 주소를 기준으로 서로 이어진다.

![종목코드가 공시와 재무제표를 잇는 흐름](./assets/dartlab-story-04-code-route.svg)

코드를 찾을 때는 세 가지 경로를 쓴다. 첫째, DART 사이트에서 회사명을 검색해 종목코드를 확인한다. 둘째, 거래소 정보 화면에서 종목코드를 확인한다. 셋째, dartlab 사이트의 검색이나 기존 글의 링크에서 코드를 확인한다. 원천 확인은 [OpenDART](https://opendart.fss.or.kr/)와 [KRX 정보데이터시스템](https://data.krx.co.kr/contents/MDC/MAIN/main/index.cmd)을 같이 보면 된다.

## 코드 하나를 바꾸면 회사가 바뀐다

이제 같은 질문을 두 회사에 던져 보자.

```python
samsung = dartlab.Company("005930")
samsung.select("IS", ["매출액", "영업이익"], freq="Y")
```

```python
hynix = dartlab.Company("000660")
hynix.select("IS", ["매출액", "영업이익"], freq="Y")
```

두 셀의 구조는 같다. 바뀐 것은 코드뿐이다. 그래서 코드는 초보자에게 가장 좋은 실습 단위다. 표 조작법은 그대로 두고 대상만 바꿀 수 있기 때문이다.

코드를 변수로 따로 빼면 더 또렷하다.

```python
code = "035420"
c = dartlab.Company(code)
c.panel("IS").head(3)
```

`code`를 바꾸면 `c`가 가리키는 회사도 바뀐다. 이 흐름은 단순해 보이지만, 나중에 여러 회사를 비교할 때 핵심이 된다. 코드를 목록으로 만들고, 같은 질문을 반복하고, 결과를 하나의 표로 합치는 방식이 모두 여기서 시작한다.

## 내 작은 코드북을 만든다

처음에는 매번 검색하지 말고 작은 코드북을 만들어 두는 편이 낫다.

아래에서 쓰는 `{}` 구조는 파이썬의 딕셔너리다. 공식 문법이 궁금하면 [Python 자료구조 문서](https://docs.python.org/3/tutorial/datastructures.html#dictionaries)를 참고하면 된다. 여기서는 딕셔너리를 회사명과 종목코드를 잇는 작은 표로 쓴다.

```python
codes = {
    "삼성전자": "005930",
    "SK하이닉스": "000660",
    "NAVER": "035420",
}

code = codes["SK하이닉스"]
c = dartlab.Company(code)
c.select("IS", ["매출액", "영업이익"], freq="Y")
```

이 코드는 화려하지 않다. 하지만 초보자에게는 좋은 습관이다. 회사명을 눈으로 고르고, 실제 실행은 코드로 한다. 이름과 코드를 분리해 두면 나중에 회사명을 잘못 적어 생기는 문제를 줄일 수 있다.

이 방식은 [회사 하나는 종목코드 하나](/blog/company-one-stock-code)에서 다룬 문제와 이어진다. 이름은 사람이 읽기 위한 표지판이고, 코드는 시스템이 같은 회사를 다시 찾기 위한 열쇠다. 공시 분석을 반복할수록 이 차이가 커진다.

## 코드북은 노트북의 입력칸이다

코드북을 만들었다면 그다음은 노트북 맨 위에 두는 것이다. 그래야 아래 셀들이 전부 같은 입력을 바라본다. 회사 코드를 본문 중간중간에 흩뿌리면 나중에 바꿀 곳을 놓친다.

```python
codes = {
    "삼성전자": "005930",
    "SK하이닉스": "000660",
    "NAVER": "035420",
}

target = "삼성전자"
code = codes[target]
c = dartlab.Company(code)
c.market
```

이제 아래 셀들은 `target`과 `code`를 직접 몰라도 된다. `c`만 쓰면 된다. 회사를 바꾸고 싶으면 `target = "SK하이닉스"`로 바꾸고, 아래 셀을 차례로 다시 실행한다. 지난 편에서 배운 실행 순서가 여기서 바로 쓰인다.

```python
c.select("IS", ["매출액", "영업이익"], freq="Y")
```

이 구조는 작지만 강하다. 입력칸, 데이터칸, 출력칸이 나뉘기 때문이다. 입력칸은 회사와 기간을 정한다. 데이터칸은 `Company`와 `panel`을 만든다. 출력칸은 원하는 계정과 표 모양을 보여 준다. 나중에 두 회사를 비교하거나 전종목 후보를 검증할 때도 같은 구조가 유지된다.

회사 이름을 직접 코드로 바꾸는 기능이 브라우저에서 안 된다고 해서 분석 흐름이 끊기는 것은 아니다. 오히려 처음에는 이렇게 명시적으로 쓰는 편이 좋다. 내가 어떤 코드를 보고 있는지 숨겨지지 않기 때문이다. 자동 검색은 편하지만, 초보자에게는 대상 확인 단계를 건너뛰게 만들 수 있다.

코드북을 오래 쓰려면 출처도 같이 적어 두는 편이 좋다. 예를 들어 어떤 코드는 DART에서 확인했고, 어떤 코드는 거래소 화면에서 확인했는지 메모해 둔다. 회사명이 비슷한 경우에는 이 메모가 꽤 중요하다. 지주회사, 사업회사, 우선주, 스팩처럼 이름이 닮은 항목이 섞이면 눈으로는 맞아 보이지만 코드가 다를 수 있다.

또 하나의 습관은 첫 출력에 회사의 큰 표를 조금만 여는 것이다. 바로 복잡한 분석으로 들어가지 말고 `panel("IS").head(2)`처럼 앞 두 줄만 확인한다. 화면에 나온 계정이 내가 생각한 업종과 완전히 다르면 코드를 다시 의심해야 한다. 코드 검산은 시간을 낭비하는 절차가 아니라, 뒤에서 더 큰 시간을 아끼는 절차다.

이 원칙은 공시 원문을 열 때도 같다. DART에서 검색한 회사명과 dartlab에서 넣은 코드가 같은 회사를 가리키는지 먼저 맞춘다. 그다음 손익계산서, 재무상태표, 현금흐름표를 본다. 대상을 정확히 잡는 일은 너무 기초라서 건너뛰기 쉽지만, 잘못 잡으면 모든 분석이 처음부터 다른 회사 이야기가 된다.

## 미국 회사는 여섯 자리 코드가 아니다

국내 회사는 여섯 자리 종목코드를 쓴다. 미국 회사는 티커를 쓴다. 애플은 `AAPL`, 엔비디아는 `NVDA` 같은 식이다. 미국 공시의 원천은 [SEC EDGAR](https://www.sec.gov/edgar)다. 구조 자체는 다르지만, "회사를 먼저 정확히 지목한다"는 원칙은 같다.

이번 편의 실행 셀은 국내 회사로 제한한다. 브라우저에서 미국 데이터를 받는 과정은 시간이 더 걸리고, 초보자에게는 코드와 티커의 차이가 먼저 중요하다. 미국 공시의 읽는 법은 [EDGAR 전부 알기](/blog/everything-about-edgar)에 따로 묶어 두었다.

국내 공시를 깊게 읽으려면 [DART 전부 알기](/blog/everything-about-dart)와 [사업보고서 읽는 법](/blog/reading-business-reports)을 같이 보면 좋다. 지금 우리가 여는 표는 결국 사업보고서와 분기보고서의 재무제표에서 나온다. dartlab은 그 원문을 사람이 비교하기 쉬운 격자로 바꿔 놓는 역할을 한다.

## 같은 코드로 표 세 장을 연다

회사를 정확히 잡았다면, 그다음은 2편에서 배운 세 장이다.

```python
c = dartlab.Company("005930")

is_ = c.panel("IS")
bs = c.panel("BS")
cf = c.panel("CF")

is_.shape, bs.shape, cf.shape
```

손익계산서, 재무상태표, 현금흐름표가 같은 회사 코드 아래 열린다. 같은 회사의 세 표를 볼 때는 이 일관성이 중요하다. `IS`는 삼성전자이고 `BS`는 SK하이닉스가 되는 식으로 섞이면 분석은 바로 깨진다.

그래서 노트북에서 회사를 바꿀 때는 보통 맨 위 코드 셀 하나만 바꾸고, 아래 셀들을 차례로 다시 실행한다. 이렇게 해야 모든 표가 같은 회사를 바라본다.

```python
code = "000660"
c = dartlab.Company(code)

c.panel("IS").head(2)
```

이 한 칸을 바꾸고 아래 셀을 다시 누르면, 같은 노트북이 SK하이닉스 분석 노트북으로 바뀐다. 복잡한 도구를 배우는 것이 아니라, 좋은 템플릿을 만들고 대상 코드만 바꾸는 습관을 배우는 것이다.

## 코드가 맞는지 검산하는 습관

코드는 짧지만 틀리기 쉽다. `005930`에서 0 하나를 빼면 다른 형식이 되고, 숫자 하나를 바꾸면 전혀 다른 회사가 된다. 그래서 첫 셀에서는 바로 큰 분석을 하지 말고 시장과 표 일부를 확인한다.

```python
c = dartlab.Company("005930")
c.market
```

```python
c.panel("IS").head(2)
```

시장 확인, 표 앞부분 확인, 그다음 원하는 계정 조회. 이 순서가 안전하다. 이름 검색이 안 된다고 불평하기 전에, 코드를 기준으로 대상이 정확히 잡혔는지 보는 습관이 더 중요하다.

이 습관은 나중에 전종목 스캔을 볼 때도 이어진다. 시장 표에서 후보 회사를 찾고, 다시 그 회사 코드로 돌아와 원 재무제표를 확인해야 한다. 후보 표만 보고 결론을 내리면 원천 숫자의 기준을 놓치기 쉽다.

## 이렇게 오해하면 안 된다

첫째, 종목코드는 회사의 영원한 본명이 아니다. 상장폐지, 합병, 분할, 재상장 같은 사건이 있으면 코드와 대상의 해석이 달라질 수 있다. 일반적인 분석에서는 안정적이지만, 특수한 기업 사건에서는 원 공시를 확인해야 한다.

둘째, 회사 이름을 코드로 자동 변환하지 않는다고 해서 dartlab이 회사를 모르는 것은 아니다. 브라우저 글의 실행 경계를 분명히 하기 위한 선택이다.

셋째, 코드가 맞다고 투자 판단이 맞아지는 것은 아니다. 코드는 출발점일 뿐이다. 표를 열고, 기간을 고르고, 계정의 뜻을 확인해야 한다.

## 다음 편으로 넘어가기 전 행동 검사

이번 편의 행동 검사는 회사 코드 하나로 노트북 전체가 바뀌는지 확인하는 것이다. 먼저 코드북에 세 회사를 넣는다. 삼성전자, SK하이닉스, NAVER 정도면 충분하다. 그다음 `target` 이름만 바꿔 가며 `c.market`과 `c.panel("IS").head(2)`가 정상으로 나오는지 본다. 여기서 중요한 것은 멋진 표가 아니라 대상이 제대로 바뀌는지다.

두 번째 검사는 실수 방지다. 코드 문자열에서 앞의 0을 일부러 빼 보라. 예를 들어 `005930`을 숫자처럼 쓰면 앞의 0이 사라진다. 종목코드는 계산할 숫자가 아니라 글자열이다. 그래서 따옴표 안에 넣어야 한다. `005930`은 여섯 자리 코드이고, `5930`은 다른 입력이다. 이 차이를 몸으로 겪어야 나중에 코드를 다룰 때 덜 실수한다.

세 번째 검사는 원천 확인이다. DART 사이트에서 같은 회사명을 검색해 화면에 보이는 종목코드와 노트북의 코드가 맞는지 확인한다. 여기서 많은 초보자가 계열사 이름을 잘못 고른다. 비슷한 이름이 많을수록 첫 단계에서 확인해야 한다. 확인을 끝낸 뒤에야 손익계산서와 재무상태표를 여는 의미가 생긴다.

이 행동 검사를 통과하면 다음 편의 기간 실습이 쉬워진다. 회사가 정확히 고정되어 있어야 연간과 분기 차이를 볼 수 있다. 대상이 틀린 상태에서 기간을 바꾸는 것은 질문을 정교하게 만드는 것이 아니라, 다른 회사의 표를 더 정교하게 잘못 읽는 일이다. 그래서 회사 코드 확인은 가장 앞에 둔다.

## 이번 편에서 일부러 하지 않는 것

이번 편은 모든 회사 코드를 외우게 하려는 글이 아니다. 코드는 외우는 것이 아니라 확인하는 것이다. 자주 보는 회사 몇 곳만 작은 코드북에 넣어 두고, 낯선 회사는 원천 화면에서 다시 확인하면 된다. 외우려고 하면 빠르고, 확인하려고 하면 정확하다. 공시 분석에서는 정확한 쪽이 먼저다.

또한 이번 편은 이름 검색 기능을 약속하지 않는다. 브라우저에서 회사 이름을 입력하면 자동으로 코드를 찾아 준다고 말하면 편해 보이지만, 실행 환경의 경계를 흐린다. 여기서는 코드가 준비된 뒤 `Company`로 연다. 이름 검색, 대량 코드 매핑, 최신 상장 목록 갱신은 로컬 설치본이나 별도 데이터 작업에서 다루는 것이 맞다.

마지막으로 코드를 투자 아이디어처럼 다루지 않는다. `005930`을 넣었다고 삼성전자 분석이 끝난 것이 아니다. 이제 겨우 올바른 문을 연 것이다. 이 문을 연 뒤에 기간을 정하고, 계정을 고르고, 원천 공시와 비교해야 한다. 코드 수업을 앞에 둔 이유는 그 다음 모든 수업이 같은 대상을 바라보게 하기 위해서다.

## 다음 편에서 할 것

이제 회사를 정확히 여는 법을 배웠다. 다음은 표의 방향이다. 같은 회사라도 연간으로 보느냐, 분기로 보느냐에 따라 질문이 달라진다. 매출이 5년 동안 커졌는지 보는 질문과, 최근 두 분기가 꺾였는지 보는 질문은 다르다.

다음 편 [재무제표 기간, Y와 Q 조회](/blog/the-grid)에서는 `freq="Y"`와 `freq="Q"`를 비교한다. 같은 `select` 호출이 어떤 기간 격자를 돌려주는지 직접 확인하고, 연간과 분기를 섞어 읽을 때 생기는 오해를 막는다.
