## 코드셀은 작은 계산기가 아니다

[DART 공시분석, 설치 없이](/blog/what-is-dartlab)에서는 브라우저에서 `dartlab.Company("005930")`를 눌러 첫 표를 열었다. [재무제표, 파이썬 한 줄](/blog/call-financial-statements)에서는 손익계산서, 재무상태표, 현금흐름표를 같은 방식으로 불러왔다. 여기까지는 "누르면 표가 나온다"는 경험이다.

이번 편에서 배울 것은 조금 다르다. 코드셀은 독립된 계산기가 아니다. 위 셀에서 만든 회사와 표를 아래 셀이 기억한다. 그래서 노트북은 글이면서 동시에 작업대가 된다. 앞에서 회사를 고르고, 다음 칸에서 손익계산서를 열고, 그다음 칸에서 같은 표의 일부만 다시 보는 식으로 생각을 이어 갈 수 있다.

![브라우저 안에서 이어지는 코드셀 작업대](./assets/dartlab-story-03-codecell.webp)

이 차이를 모르면 셀을 누르는 순서가 꼬였을 때 당황한다. 어떤 칸은 잘 되는데 어떤 칸은 이름을 모른다고 하고, 방금 고친 값이 다음 표에 반영되지 않는 것처럼 보인다. 대부분은 데이터 문제가 아니라 **실행 순서 문제**다. 투자나 회계 판단 이전에, 노트북이 어떻게 기억하는지 알아야 한다.

## 첫 셀은 회사를 기억시킨다

먼저 회사를 하나 만든다.

```python
import dartlab

c = dartlab.Company("005930")
c.market
```

이 셀은 두 가지 일을 했다. `dartlab`을 불러왔고, `c`라는 이름에 삼성전자를 넣었다. 마지막 줄의 `c.market`은 지금 이 회사가 어느 시장 데이터로 연결되는지 보여 준다. `KR`이면 한국 [DART](https://dart.fss.or.kr/) 쪽으로 간다.

중요한 것은 화면에 `KR`이 찍혔다는 사실보다 `c`가 남았다는 사실이다. 다음 셀은 `import dartlab`을 다시 하지 않아도 되고, `Company("005930")`을 다시 만들지 않아도 된다. 같은 노트북 안에서는 앞 셀이 만든 이름을 뒤 셀이 이어 받는다.

```python
is_ = c.panel("IS")
is_.head(3)
```

여기서 `c`는 새로 만든 것이 아니다. 바로 위 셀이 만든 그 회사다. `is_`는 손익계산서 표를 담는 이름이다. 파이썬에서는 `is`가 이미 문법에 쓰이는 단어라서, 변수 이름으로 쓰지 않고 뒤에 밑줄 하나를 붙였다.

이제 손익계산서 표도 노트북에 남았다.

```python
is_.shape
```

삼성전자 손익계산서는 현재 브라우저 데이터 기준으로 `(36, 43)` 모양으로 열린다. 앞 숫자는 항목 수, 뒤 숫자는 열 수다. 여러분의 화면에서 숫자가 나중에 조금 달라질 수 있다. 공시는 새로 쌓이고 정정공시도 나오기 때문이다. 여기서 배울 것은 숫자 하나가 아니라, 앞 셀에서 만든 `is_`를 뒤 셀이 그대로 썼다는 구조다.

## 위에서 아래로 실행해야 하는 이유

처음 보는 사람은 글을 읽듯 중간 셀부터 누르기도 한다. 그럴 수 있다. 그런데 `is_.shape`를 먼저 누르면 브라우저는 `is_`가 무엇인지 모른다. 아직 그 이름을 만든 적이 없기 때문이다.

노트북은 페이지를 위에서 아래로 자동으로 다 이해하지 않는다. 사용자가 실행한 셀만 기억한다. 순서는 다음처럼 잡으면 된다.

![코드셀이 같은 실행 상태를 공유하는 흐름](./assets/dartlab-story-03-state-flow.svg)

첫째, `import dartlab`과 `Company`를 실행한다. 둘째, 그 회사로 `panel`이나 `select`를 실행한다. 셋째, 만들어진 표를 `head`, `shape`, `null_count` 같은 표 조작으로 본다.

```python
sales = c.select("IS", ["매출액", "영업이익"], freq="Y")
sales
```

```python
sales.head(1)
```

두 번째 셀은 `sales`를 새로 만들지 않는다. 바로 앞 셀의 결과를 다시 보여 줄 뿐이다. 이게 노트북의 장점이다. 한 번 무거운 표를 열고, 그 표를 여러 방향으로 잘라 볼 수 있다.

반대로 앞 셀을 고쳤다면 뒤 셀도 다시 눌러야 한다. 예를 들어 `freq="Y"`를 `freq="Q"`로 바꾸고 첫 셀만 다시 실행하면, 화면 아래쪽에 이미 찍혀 있던 예전 결과가 자동으로 바뀌지 않는다. 아래 셀도 다시 실행해야 같은 흐름이 맞춰진다.

## 이름은 붙이는 순간부터 살아 있다

파이썬에서 `=`는 같다는 뜻보다 "이 이름에 이 값을 붙인다"에 가깝다. 투자자가 처음 데이터 코드를 배울 때 가장 먼저 익혀야 하는 감각이다.

변수와 이름 붙이기 자체가 낯설다면 [Python 공식 튜토리얼](https://docs.python.org/3/tutorial/introduction.html)의 기본 계산과 변수 예시를 먼저 훑어도 좋다. 이 글에서는 그 문법을 공시 데이터 노트북 안에서 어떻게 쓰는지만 다룬다.

```python
target_code = "005930"
company = dartlab.Company(target_code)
company.select("IS", ["매출액"], freq="Y")
```

여기서는 회사 코드를 `target_code`라는 이름에 넣고, 그 코드를 이용해 `company`를 만들었다. 다음 편 [DART 종목코드, 회사 열기](/blog/pick-company-by-code)에서 이 방식을 더 자세히 쓴다. 지금은 이름이 쌓이는 순서만 보면 된다.

같은 이름에 다른 값을 다시 붙일 수도 있다.

```python
target_code = "000660"
company = dartlab.Company(target_code)
company.select("IS", ["매출액"], freq="Y")
```

이 셀을 실행하면 `company`는 이제 SK하이닉스를 가리킨다. 위에 찍혀 있던 삼성전자 표가 지워지는 것은 아니다. 화면에 남은 결과는 과거 출력이고, 변수 이름이 가리키는 대상은 새로 바뀐 상태다.

이 차이를 이해하면 노트북이 훨씬 덜 무섭다. 화면은 기록이고, 변수는 현재 상태다. 기록과 현재 상태가 다를 수 있으므로, 중요한 분석은 위에서 아래로 다시 실행해 흐름을 맞추는 습관이 필요하다.

## 노트북 생성은 글을 내 작업장으로 복사하는 일이다

본문의 코드셀은 읽는 사람 모두에게 같은 예제를 제공한다. 하지만 분석은 결국 내 회사, 내 질문, 내 순서로 바꿔야 한다. 그래서 글 아래에는 "노트북 생성하기"가 붙는다.

그 버튼은 글을 다른 글로 바꾸는 기능이 아니다. 지금 본문에 있는 코드셀들을 여러분의 노트북 한 권으로 복사한다. 거기서는 셀을 더하고, 삭제하고, 순서를 바꾸고, 회사 코드를 바꿀 수 있다. 위에서 아래로 이어지는 상태 모델은 그대로다.

[Pyodide로 만든 브라우저 dartlab](/blog/pyodide-dartlab-lite)을 읽으면 이 구조가 왜 설치 없이 가능한지 더 자세히 알 수 있다. 브라우저 안에 파이썬 실행 환경이 올라오고, 그 안에서 [polars](https://pola.rs/) DataFrame이 표를 다룬다. 여러분의 컴퓨터에 파이썬을 따로 설치하지 않아도 되는 이유다.

다만 브라우저는 모든 것을 허용하지 않는다. 주가, 뉴스, 수급처럼 외부 서버에 직접 요청해야 하는 데이터 수집은 여기서 안 됩니다. 브라우저 보안 정책과 데이터 제공처의 제한 때문이다. 그런 작업은 [dartlab 쉽게 시작하기](/blog/dartlab-easy-start)처럼 로컬 파이썬을 설치한 뒤 다루는 영역이다.

## 저장하는 셀과 보여 주는 셀을 나눈다

노트북을 조금만 쓰다 보면 셀마다 역할을 나누는 편이 편하다. 어떤 셀은 값을 저장하고, 어떤 셀은 그 값을 보여 준다. 이 구분이 생기면 분석 흐름이 덜 엉킨다.

저장하는 셀은 보통 위쪽에 둔다. 회사 코드, 회사 객체, 자주 쓸 표를 만든다.

```python
code = "005930"
c = dartlab.Company(code)
is_ = c.panel("IS")
```

보여 주는 셀은 그 아래에 둔다. 같은 `is_`를 여러 방식으로 살펴본다.

```python
is_.head(5)
```

```python
is_.shape
```

이렇게 나누면 회사 코드를 바꿀 때 어디를 고쳐야 하는지 분명하다. 맨 위 입력 셀의 `code`만 바꾸고, 아래 셀을 순서대로 다시 실행하면 된다. 반대로 표를 보는 방식만 바꾸고 싶다면 아래 출력 셀만 바꾸면 된다.

초보자가 자주 하는 실수는 한 셀에 모든 것을 넣는 것이다. 회사를 만들고, 표를 열고, 계산하고, 해석까지 한 칸에 넣으면 처음에는 빨라 보인다. 하지만 나중에 회사만 바꾸거나 기간만 바꾸고 싶을 때 어디를 고쳐야 할지 모른다. 노트북은 한 번에 긴 코드를 쓰는 곳이 아니라, 생각을 작은 단계로 남기는 곳이다.

이 습관은 다음 편부터 계속 쓴다. 회사 코드는 위에서 정하고, 재무제표 표는 중간에서 만들고, 마지막에 필요한 계정이나 기간만 바꿔 본다. 그러면 글을 읽는 노트북이 아니라 내 질문을 담는 노트북이 된다.

처음부터 다시 실행해야 하는 순간도 알아 두자. 회사 코드를 바꿨을 때, 기간을 연간에서 분기로 바꿨을 때, 표를 만드는 셀의 계정 이름을 바꿨을 때는 아래 셀을 다시 눌러야 한다. 반대로 마지막 출력 방식만 바꿨다면 그 셀만 다시 실행해도 된다. 어디서 값이 만들어졌는지 알면 다시 누를 범위가 보인다.

이 감각은 나중에 계산식이 들어올수록 중요해진다. 매출과 영업이익을 뽑고, 그 둘로 마진을 계산하고, 다시 그래프를 그리는 흐름에서는 앞 셀 하나가 바뀌면 뒤 셀 전체가 영향을 받는다. 그래서 노트북을 쓸 때는 "이 셀은 무엇을 만들고, 다음 셀은 무엇을 소비하는가"를 계속 의식해야 한다.

## 오류가 났을 때 먼저 볼 것

초보자가 처음 만나는 오류는 대개 셋이다.

첫째, `NameError`다. 이름을 모른다는 뜻이다. 거의 항상 앞 셀을 실행하지 않았거나, 변수 이름을 다르게 적었다는 뜻이다. `sales`를 만들었는데 아래에서 `sale`이라고 쓰면 브라우저는 그것이 무엇인지 모른다.

둘째, 빈 결과다. `select`에서 계정 이름이 맞지 않거나, 그 회사가 그 계정을 공시하지 않았을 수 있다. 2편에서 말했듯 같은 경제적 의미라도 회사마다 계정 이름은 다를 수 있다. 이때는 표 전체를 먼저 보고 실제 항목명을 확인한다.

```python
c.panel("IS").head(10)
```

셋째, 오래 걸리는 첫 실행이다. 처음 셀은 브라우저가 파이썬 환경과 dartlab을 내려받느라 느리다. 첫 실행이 끝난 뒤에는 같은 페이지 안에서 훨씬 빠르게 돈다. 실행이 느리다고 해서 DART 데이터가 틀린 것은 아니다.

외부 원천을 확인하고 싶으면 [OpenDART](https://opendart.fss.or.kr/)와 [SEC EDGAR](https://www.sec.gov/edgar)를 보면 된다. 국내 회사는 DART가 원천이고, 미국 회사는 EDGAR가 원천이다. dartlab은 그 원천을 읽기 좋은 표로 바꾸는 도구다.

## 이렇게 오해하면 안 된다

첫째, 셀을 고쳤다고 아래 결과가 자동으로 새로 계산되는 것은 아니다. 바꾼 셀부터 아래로 다시 눌러야 한다.

둘째, 화면에 남아 있는 표가 현재 변수 상태와 항상 같지는 않다. 화면은 과거 실행의 기록이고, 변수는 마지막 실행의 결과다.

셋째, 브라우저 노트북은 설치본의 모든 기능을 대신하지 않는다. 공시 표를 읽고 실습하는 데 최적화되어 있고, 가격 데이터나 뉴스 수집은 로컬에서만 됩니다.

## 다음 편으로 넘어가기 전 행동 검사

이번 편을 제대로 익혔는지는 설명을 외웠는지가 아니라, 같은 노트북 안에서 값을 이어 쓸 수 있는지로 확인한다. 먼저 첫 셀에서 `code = "005930"`을 만들고, 그 아래에서 `c = dartlab.Company(code)`를 만든다. 그다음 셀에서 `c.panel("IS").head(3)`을 실행한다. 여기까지 되면 회사 코드, 회사 객체, 표 출력이 순서대로 이어진 것이다.

그 다음에는 맨 위의 `code`만 `"000660"`으로 바꾼다. 그리고 아래 셀을 차례로 다시 실행한다. 표가 SK하이닉스로 바뀌면 통과다. 만약 아래 표가 그대로라면, 코드를 바꾼 셀만 실행하고 표를 여는 셀을 다시 누르지 않은 것이다. 이 실수는 초보자만 하는 것이 아니다. 오래 쓰는 사람도 노트북이 길어지면 자주 만난다.

마지막으로 일부러 중간 셀부터 실행해 본다. `sales.head(1)`처럼 앞에서 만들어야 할 이름을 먼저 눌러 보면 브라우저가 이름을 모른다고 말할 것이다. 그 오류를 무서워할 필요는 없다. 오히려 좋은 확인이다. "이 이름은 어느 셀에서 만들어졌지"라고 되짚는 습관이 생기면, 앞으로 나오는 대부분의 실습 오류를 스스로 풀 수 있다.

이 행동 검사가 끝나면 여러분은 코드셀을 단순히 누르는 사람이 아니라, 노트북의 상태를 관리하는 사람이 된다. 다음 편에서 회사 코드를 바꾸고, 그다음 편에서 기간을 바꾸는 실습은 모두 이 감각 위에 올라간다. 위에서 아래로 실행하고, 바꾼 곳부터 다시 실행한다. 이 두 문장만 기억해도 초보 단계의 절반은 지나온 것이다.

## 이번 편에서 일부러 하지 않는 것

이번 편은 파이썬 문법 전체를 가르치지 않는다. 반복문, 함수, 그래프, 파일 저장은 뒤로 미룬다. 지금 필요한 것은 셀 하나가 다음 셀에 무엇을 남기는지 이해하는 것이다. 이 감각 없이 문법을 많이 배우면 코드가 길어질수록 더 빨리 길을 잃는다.

또한 이번 편은 투자 판단을 다루지 않는다. 매출액이 얼마이고 영업이익이 얼마인지보다, 그 숫자를 담은 표가 어느 셀에서 만들어졌는지가 먼저다. 데이터 분석은 숫자 해석 전에 실행 흐름이 맞아야 한다. 실행 흐름이 틀리면 맞는 숫자도 틀린 문장으로 이어진다.

마지막으로 브라우저 노트북을 로컬 개발 환경처럼 다루지 않는다. 여기서는 글을 읽으면서 안전하게 공시 표를 눌러 보는 것이 목적이다. 대규모 수집, 자동 저장, 실시간 데이터 결합은 나중에 로컬 설치본에서 다룬다. 경계를 좁게 잡아야 첫 학습이 안정된다.

## 다음 편에서 할 것

이제 여러분은 코드셀을 누르는 법이 아니라, 코드셀이 어떻게 이어지는지 알게 됐다. 다음 편은 회사를 고르는 일이다. 브라우저에서는 회사 이름을 코드로 자동 변환하지 않는다고 1편에서 말했다. 그러면 초보자는 어디서 여섯 자리 코드를 찾아야 할까.

다음 편 [DART 종목코드, 회사 열기](/blog/pick-company-by-code)은 그 질문에 답한다. 회사명, 종목코드, `Company` 사이를 분명히 나누고, 코드 하나를 바꿔 다른 회사의 재무제표를 여는 습관을 만든다.
