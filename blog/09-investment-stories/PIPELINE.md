# 투자이야기 파이프라인 (09-investment-stories)

> **뼈대는 [blog/PIPELINE.md](../PIPELINE.md)·[BLOG.md](../BLOG.md)를 그대로 준용한다.** 이 문서는 회사 심층편·데이터 리포트·기술이야기와 다른 **델타(투자이야기 특화)만** 적는다. 강행규칙은 `CLAUDE.md`.

## 1. 정체성

투자이야기는 **"투자자가 시장을 읽을 때 쓰는 언어와 프레임의 왜?"**다.

- **주어 = 투자 개념과 시장 언어.** 주가, 금리, 환율, 물가, 컨센서스, 목표주가, 밸류에이션, 지지선, 저항선, 이동평균, RSI, MACD, 거래량, 기술투자 같은 프레임을 설명한다.
- **착지점 = 다음에 무엇을 볼지.** 매수·매도 결론이 아니라 독자가 다음 차트, 다음 공시, 다음 데이터에서 무엇을 확인해야 하는지로 닫는다.
- **회사·기술·데이터 글은 참고글.** 한 회사나 산업을 주어로 삼지 않는다. 기존 기업이야기·기술이야기·데이터 리포트에 이미 설명한 내용이 있으면 새 글에서 반복하지 말고 링크로 연결한다.
- **투자권유 금지.** "지지선은 얼마니까 산다", "RSI가 낮으니 오른다"처럼 확정 결론으로 쓰지 않는다. 지지선과 보조지표는 시나리오를 나누는 도구이지 예언이 아니다.

## 2. 준용

Phase 0 데이터 완주 / Phase 1 적대 토론 기획 / Phase 2.5 마스터라이터 편집 게이트 / Phase 4 독자 루프 / 수치 6원칙·검증표 / 이미지·비주얼 기획 / `audit_seo.py` SEO 점수 95 이상 / `auditBlog.py --gate` 발행 하드 게이트를 그대로 따른다.

공통 프레임은 같다. 투자이야기도 기획 단계에서 관통선, 핵심 인싸이트, 막 구조, 이야기 깊이, 참고글 연결, 차트·표·이미지, 오독 방지를 모두 정한다. `brief.json` 없이 글을 먼저 쓰지 않는다.

## 3. 주제 라우팅

1. **주가 구조**: 지지선, 저항선, 추세, 박스권, 신고가, 갭, 거래량, 변동성.
2. **경제 변수**: 금리, 환율, 물가, 경기 사이클, 유동성, 신용 스프레드.
3. **증권사 언어**: 목표주가, 컨센서스, 투자의견, overweight, neutral, buy, revision, 리레이팅.
4. **투자 용어**: PER, PBR, ROE, EV/EBITDA, 베타, 듀레이션, 마진콜, 공매도, 숏커버.
5. **기술적투자·보조지표**: 이동평균, RSI, MACD, 볼린저밴드, OBV, 피보나치, 거래대금.
6. **기술투자 프레임**: AI, HBM, 로봇, 배터리, 바이오처럼 기술 서사가 주가와 밸류에이션으로 번역되는 방식.

## 4. 참고글 연결 라우터

착수 전 기존 글을 먼저 찾는다.

1. **개념 참고글**: 같은 투자 개념을 다룬 투자이야기가 있으면 먼저 연결한다.
2. **사례 참고글**: 특정 회사·업종 사례가 필요하면 기업이야기·데이터 리포트를 연결한다.
3. **메커니즘 참고글**: 기술 원리나 공정 병목 설명이 필요하면 기술이야기·산업 지도를 연결한다.

본문에는 최소 2개 이상의 내부 참고글을 넣는다. 선행 글이 핵심 설명을 이미 갖고 있으면 한 문단으로만 요약하고, "자세한 사례는 ..." 형태로 링크한다. 참고글이 억지로 붙으면 실패다. 링크는 독자가 다음 질문으로 자연스럽게 이동할 때만 둔다.

`brief.json` 에는 `relatedPosts` 를 둔다.

```json
{
  "relatedPosts": {
    "searches": ["지지선 이동평균 HBM", "컨센서스 목표주가"],
    "links": [
      {
        "path": "/blog/hbm-stack-packaging-test",
        "title": "HBM 공정 네트워크 글",
        "reason": "기술투자 사례로 연결",
        "placement": "기술투자 프레임을 설명한 뒤"
      }
    ],
    "placementRule": "개념을 반복하지 않고 선행 글이 필요한 문단 뒤에 배치"
  }
}
```

## 5. 글 구조

고정 템플릿은 아니지만 기본 뼈대는 이렇게 둔다.

1. 독자 질문: "주가가 떨어지면 지지선은 어디라고 말하는가?"
2. 용어 풀기: 지지선·저항선·이동평균 같은 말을 시장 참여자의 행동으로 번역한다.
3. 데이터 기준: 기간, 봉 단위, 가격 기준, 거래량 기준, 표본 출처를 먼저 못박는다.
4. 비주얼 해부: 차트·표·계산식을 본문 중간에 넣고, 어떤 판단을 돕는지 설명한다.
5. 참고글 연결: 회사·기술·데이터 사례가 필요한 순간에 내부 글을 붙인다.
6. 틀리는 조건: 보조지표가 깨지는 국면, 뉴스·공시·유동성 변화, 기준선 재설정 조건을 쓴다.
7. 다음에 볼 것: 독자가 다음 차트·공시·경제지표에서 확인할 체크리스트로 닫는다.

## 6. 비주얼

비주얼은 기획에서 먼저 정한다.

- **가격·지표 차트**: 가격, 이동평균, 거래량, RSI, MACD 같은 계열을 기간과 기준까지 명시한다.
- **개념 도해**: 지지선·저항선·리레이팅·컨센서스 변화를 단순한 구조도로 보여준다.
- **비교 표**: 증권사 표현, 투자 용어, 보조지표의 쓰임과 오독 조건을 비교한다.
- **사례 연결 표**: 참고글, 연결 이유, 독자가 이어서 확인할 질문을 표로 묶는다.

차트는 결론을 대신하지 않는다. "이 선을 깨면 무조건 하락"이 아니라 "이 기준이 깨지면 기존 시나리오를 다시 점검한다"로 쓴다.

## 7. 발행 계약

- 폴더: `blog/09-investment-stories/{NN}-{slug}/index.md`
- frontmatter: `category: investment-stories`, `series: investment-stories`, `topicSlug` 필수.
- 기본적으로 `stockCode` 를 달지 않는다. 주어는 한 회사가 아니라 투자 개념이다.
- 본문 하한: 5,000자. 목표: 8,000자 이상. 길이는 용어·기준·반례·사례·비주얼 설명의 결과여야 한다.
- 내부 참고글 2개 이상. 선행 글이 없으면 `brief.json` 에 검색어와 부재 사유를 남기고, 본문에는 억지 링크를 넣지 않는다.
- 기술적투자·보조지표 글은 기간, 봉 단위 또는 데이터 기준, 거래량 또는 기준선 설명을 포함한다.
- "투자권유가 아니다" 수준의 면책 문구만으로 통과하지 않는다. 왜 틀릴 수 있는지, 어느 조건에서 기준이 바뀌는지를 본문에서 설명해야 한다.
- `auditBlog.py --gate` 대상이다. 실사 OG, assets 사진, 본문 이미지, `brief.json`, `visuals[]`, `imagePlan[]`, `relatedPosts`, `evidenceMap`, 92점 루프 증거가 있어야 한다.
