# 브라우저 노트북 런타임

## 목표

설치 없이 브라우저만으로 로컬 노트북에 가까운 실행 경험을 만든다. 브라우저 탭이 Python 커널, 파일 시스템, DartLab 실행 상태를 직접 소유하며 별도 실행 서버를 필수로 두지 않는다.

이 작업은 DartLab의 공개 Python 호출계약을 늘리지 않는다. 노트북 내부 `ExecutionEngine`의 실행 능력만 확장한다.

## 기본 구조

1. 전용 Web Worker가 Pyodide와 Python 상태를 소유한다.
2. `/workspace`는 노트북 ID별 OPFS 디렉터리에 연결하고 지원하지 않는 브라우저에서는 MEMFS로 동작한다.
3. 교차 출처 격리가 가능하면 `SharedArrayBuffer`로 Python에 SIGINT를 전달한다.
4. 격리가 불가능하면 실행 워커를 종료하고 새 커널을 올린다.
5. 하드 중단 뒤 노트북 문서와 OPFS 파일은 유지하고 Python 힙과 커널 종속 캐시는 버린다.

## 체크포인트 실험

`tests/_attempts/webNotebookRuntime`에서 Pyodide 0.27.5, DartLab 0.10.9 wheel, Polars를 실제로 적재해 WASM 메모리 체크포인트 그래프를 검증했다.

검증한 동작:

- 실패한 실행이 변경한 미확정 힙을 이전 상태로 복원
- 같은 부모에서 갈라진 두 상태 사이의 양방향 전환
- Polars DataFrame 변경과 복원
- 복원 뒤 Python 인터프리터의 연속 실행
- OPFS에 체크포인트 원장 저장

복원은 마지막 저장 상태의 해시를 신뢰하지 않고 현재 WASM 힙을 다시 해시한다. 실행 도중 예외가 발생하면 저장되지 않은 변경이 힙에 남기 때문에 이 재검사가 없으면 rollback이 누락된다.

## 실측 결과

| 항목 | 결과 |
|---|---:|
| 전체 시나리오 | 8.562초 |
| 기준 힙 복사본 | 163,643,392 bytes |
| 상태별 변경분 | 5,767,168~14,417,920 bytes |
| 예외 복원 | 통과 |
| 분기 복원 | 통과 |
| Polars 복원 | 통과 |
| OPFS 영속성 | 통과 |

기준 힙만 약 156MB를 추가로 사용한다. 따라서 체크포인트 자동 생성은 기본 기능으로 채택하지 않는다. 현재 구현은 256MB 저장 상한을 둔 명시적 실험 capability이며 UI에서는 노출하지 않는다.

## 제품 적용 범위

현재 기본 적용:

- OPFS 기반 `/workspace` 영속화
- 노트북 ID별 OPFS 작업공간 격리
- 노트북별 `.dartlab/requirements.json` 패키지 manifest
- `/workspace/requirements.txt` 기반 패키지 복구
- `%pip install ...`와 패키지 패널 설치 요청의 동일한 영속 경로
- 셀 실행 중지 버튼
- 격리 환경의 소프트 중단
- 일반 환경의 워커 재시작 중단
- 하드 중단 뒤 OPFS 파일 복구와 노트북 재부착
- 하드 중단 뒤 노트북별 패키지 요구사항 재설치

현재 실험 적용:

- content-addressed WASM 메모리 체크포인트
- 부모 상태를 따르는 delta 그래프
- 상태 ID 기반 분기 복원
- 전체 그래프 256MB 상한

## 다음 발전 단계

1. 체크포인트 전에 Python 객체와 allocator 메타데이터가 안정된 idle 경계인지 검사한다.
2. 전체 64KiB 페이지 해시 비용을 측정하고 dirty page 추적 가능성을 검증한다.
3. 루트 힙 복사본을 압축하거나 OPFS로 내보내 브라우저 RAM 점유를 줄인다.
4. 패키지 wheel과 데이터 파일을 OPFS 캐시에 두어 새 커널의 재기동 시간을 줄인다.
5. 교차 출처 격리 배포 헤더를 점검해 가능한 환경에서는 소프트 중단을 기본으로 만든다.
6. 메모리 압박, 탭 종료, 저장 공간 부족, OPFS 권한 실패를 별도 브라우저 회귀 시나리오로 고정한다.

## 로컬급 기준 보강

브라우저 노트북을 로컬급으로 부르려면 단순히 Python이 도는 것만으로 부족하다. 작업공간, 설치 환경,
중단 복구가 노트북 단위로 붙어 있어야 한다.

이번 보강의 기준:

- 사용자가 패키지 패널에서 설치한 패키지는 `/workspace/.dartlab/requirements.json`에 남는다.
- 사용자가 직접 둔 `/workspace/requirements.txt`도 노트북 환경 선언으로 본다.
- 워커가 하드 중단되거나 새 커널이 뜨면 작업공간을 붙인 뒤 요구사항을 다시 설치한다.
- 셀에서 `%pip install requests`처럼 로컬 노트북에 가까운 명령을 사용할 수 있다.
- 브라우저에서 지원하지 않는 pip 옵션은 조용히 삼키지 않고 실패시킨다.

아직 남은 갭은 wheel 파일 자체의 OPFS 캐시다. 현재는 요구사항을 영속화하고 브라우저 HTTP 캐시와
micropip 설치를 이용한다. 다음 단계는 다운로드한 wheel을 노트북 외부의 런타임 캐시에 저장해 새 커널
부팅 시간을 더 줄이는 것이다.

체크포인트 기본 활성화의 졸업 기준은 복원 정확성만이 아니다. 대표 모바일 메모리 예산 안에서 루트와 두 개 상태를 유지하고, 저장과 복원이 일반 셀 실행의 체감 지연을 만들지 않아야 한다.
