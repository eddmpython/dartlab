레슨 YAML · 레지스트리 · `lessonSchema.py` 게이트는 전부 삭제했다.

## 1. 사상

브라우저에서 **실제로 도는 것만** 가르친다. 안 되는 것은 감추지 않고 그 자리에서 밝히고,
`pip install dartlab` 이후 열리는 로컬 코스로 정직하게 분리한다.

편수를 채우려고 능력 하나를 한 편으로 기계 분할하지 않는다. 편은 **사람의 질문**으로 선다.
"잘 벌고 있나", "돈 떼일 위험은 얼마인가", "이 숫자는 어디서 왔나". 능력 이름이 제목이 되는 순간
그것은 도감이지 이야기가 아니다.

독자용 문구에 "축"(axis)이라는 말을 쓰지 않는다. 내부 용어다.

## 2. 트랙 여섯

| id | 제목 | 목표 |
|---|---|---|
| `start` | 시작하기 | 설치 없이 첫 재무제표를 띄우고 노트북 조작 감을 잡는다. 첫 성공을 앞에 준다 |
| `read` | 재무제표 읽기 | 넓은 표에서 원하는 숫자를 꺼내고 직접 계산한다. 파이썬 가공을 처음 만난다 |
| `interpret` | 해석과 판단 | 수익성·신용·거시로 읽고, 자동 해석을 출처로 되짚어 검증하는 습관 |
| `market` | 전종목으로 보기 | 한 회사를 넘어 전 상장사를 한 표로. 관점을 시장으로 넓힌다 |
| `compose` | 엮어서 한 편의 분석 | 조각을 이어 한 회사를 입체로 조립하고, 에러를 넘어 내 노트북을 완성한다 |

## 3. 학습 계단

한 편은 기능 소개가 아니라 **다음 편을 읽을 자격을 만드는 작은 계단**이다. 각 편은 선행 상태,
새로 얻는 능력, 넘어가는 행동 검사를 가져야 한다. 행동 검사를 못 만들면 단독 편으로 세우지 않는다.

| 편 | 선행 상태 | 새 능력 | 넘어가는 행동 검사 |
|---|---|---|---|
| 1 | 없음 | 공시가 격자와 scan 으로 바뀐다는 전체 그림 | `005930` 을 다른 코드로 바꿔 첫 표를 다시 연다 |
| 2 | 회사 하나를 만들 수 있음 | IS, BS, CF, select, scope, 빈칸을 구분 | 같은 계정을 연결과 별도로 뽑고 차이를 말한다 |
| 3 | 본문 코드를 눌러 봄 | 셀 순서, 재실행, 노트북 생성의 상태 모델 | 새 셀을 추가해 앞 셀 변수를 재사용한다 |
| 4 | 코드로 회사를 열 수 있음 | 회사명을 종목코드로 바꾸는 절차 | 랜딩에서 코드를 찾고 `Company` 로 연다 |
| 5 | 세 재무제표를 열 수 있음 | panel 이 항목 x 기간 격자라는 모델 | `freq="Y"` 와 `"Q"` 결과 차이를 설명한다 |
| 6 | 격자 모양을 이해함 | 항목명 검색과 select 실패 처리 | 없는 계정을 넣고 빈 결과를 해석한다 |
| 7 | select 결과를 받을 수 있음 | 파이썬으로 직접 계산 | 매출액과 영업이익으로 마진을 계산한다 |
| 8 | 직접 계산한 숫자가 있음 | 숫자의 출처 추적 | 한 숫자가 어느 원천 항목에서 왔는지 되짚는다 |
| 9 | 회사 숫자를 손으로 볼 수 있음 | 인자 없는 호출로 가능한 질문 목록 확인 | analysis, scan, credit, macro 의 목록 패턴을 일반화한다 |
| 10 | 질문 목록을 볼 수 있음 | 수익성 질문을 자동 계산으로 읽기 | 자동 결과와 원 표의 매출, 이익을 대조한다 |
| 11 | 수익성 자동 결과를 의심할 수 있음 | 신용 위험 질문 | 위험 점수와 부채, 현금흐름의 연결을 말한다 |
| 12 | 여러 지표를 대조할 수 있음 | story 결과를 읽고 근거로 되돌아가기 | 문장 하나를 골라 원 표나 계산으로 검증한다 |
| 13 | 회사 안 숫자를 읽을 수 있음 | 금리와 거시 배경을 붙이기 | 회사 숫자와 macro 값의 기준 기간을 분리한다 |
| 14 | 자동 문장을 검증할 수 있음 | 자동 해석의 한계와 오답 방지 | 믿을 문장, 확인할 문장, 버릴 문장을 나눈다 |
| 15 | 한 회사 분석이 가능함 | scan 으로 전 상장사 표를 열기 | 단일 회사 질문을 시장 질문으로 바꾼다 |

## 4. 중간 삽입 정책

정렬과 URL을 분리한다. 공개 URL의 안정 키는 `topicSlug` 와 폴더명 뒤쪽 slug 다. 앞의 숫자 prefix 와
frontmatter `seriesOrder` 는 화면에 보이는 순서다. `landing/src/lib/blog/posts.ts` 는 `seriesOrder` 를
`parseInt` 로 읽으므로 `2.5`, `03a` 같은 중간 번호는 쓰지 않는다.

삽입 판단은 세 갈래다.

1. **아직 뒤 편이 발행되지 않은 구간.** 커리큘럼 번호만 다시 매긴다. 새 글을 쓸 때 폴더 prefix 와
   `seriesOrder` 를 최종 번호로 만든다.
2. **이미 발행된 뒤 편 앞에 필수 선행편을 넣어야 하는 경우.** 한 번의 기계적 정리 커밋으로 뒤 편 전체의
   폴더 prefix, `seriesOrder`, 커리큘럼 번호, 앞뒤 링크 문구를 함께 옮긴다. `topicSlug` 는 바꾸지 않는다.
   public URL 은 slug 를 쓰므로 prefix 변경 자체로 URL이 깨지지 않는다.
3. **필수 선행편이 아니라 보충 설명인 경우.** 중간 번호를 억지로 만들지 않는다. 현재 트랙 끝이나 전체 끝에
   보충편으로 발행하고, 본문 내부 링크와 `relatedPosts` 로 해당 지점에 걸어 둔다.

끼워 넣기 전 질문 세 개를 통과해야 한다.

- 이 편을 안 읽으면 다음 편의 행동 검사를 실패하는가?
- 기존 편 한 문단이나 그림으로 흡수하면 충분하지 않은가?
- 새 공개 호출계약이나 브라우저 실행 경계를 추가로 검증해야 하는가?

셋 중 첫째가 아니고 둘째가 맞으면 삽입하지 않는다. 셋째만 맞으면 8절 TODO 에 보류하고 실행 검증 뒤 결정한다.
