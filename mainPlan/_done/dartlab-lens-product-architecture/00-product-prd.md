# 00. 제품 PRD

## 0. 고정 목표

**DartLab을 DART와 EDGAR 공시를 비교 가능한 기업 데이터로 만들고, 다섯 개의 검증 가능한 분석 렌즈를 통해 기업 판단으로 연결하는 증거 중심 리서치 시스템으로 제품화한다.**

내부 엔진격 폴더와 레이어 규율은 유지한다. 외부 제품 설명은 레이어가 아니라 다음 흐름을 사용한다.

`공시 및 시장 데이터 -> 비교 가능한 기업 정보 -> 다섯 분석 렌즈 -> 판단 워크플로 -> 사용 표면`

## 1. 핵심 판정

DartLab의 문제는 엔진 수가 많다는 것이 아니다. 엔진을 깊게 만들었지만 사용자에게는 축 목록으로 노출하고, 그 위에 더 큰 제품을 계속 추가한 것이 문제다.

따라서 다음을 고정한다.

1. 현재 폴더 구조를 축소하거나 하나의 범용 엔진으로 합치지 않는다.
2. Analysis, Credit, Industry, Quant, Macro를 공개 제품으로 유지하고 개별 강화한다.
3. 축은 상세 탐색 단위로 유지하되 제품의 첫 진입점으로 사용하지 않는다.
4. 각 렌즈는 축 지식 없이 실행 가능한 대표 질문과 대표 결과를 가져야 한다.
5. Story, Simulate, Ask는 하위 렌즈의 결과와 증거를 소비한다.
6. README와 제품 UI에서 내부 레이어 번호를 사용자 정신모형으로 강요하지 않는다.
7. 신규 엔진과 신규 축보다 기존 대표 흐름 완성을 우선한다.

## 2. 제품 한 문장

**DartLab은 공시를 비교 가능한 기업 데이터로 바꾸고, Analysis, Credit, Industry, Quant, Macro 렌즈로 근거 있는 판단을 만드는 오픈소스 기업 리서치 시스템이다.**

## 3. 제품 서명

사용자는 축 이름이나 패키지 구조를 몰라도 종목과 기준시점만으로 다음 질문의 답 또는 답할 수 없는 이유를 받아야 한다.

1. 이 회사의 사업과 이익은 무엇이 움직이는가.
2. 이 회사는 부채와 유동성 위험을 감당할 수 있는가.
3. 이 회사는 산업 가치사슬에서 어디에 있고 누구와 비교해야 하는가.
4. 시장가격과 펀더멘털 사이에는 어떤 불일치가 있는가.
5. 거시환경은 산업과 기업 재무에 어떤 경로로 전달되는가.
6. 다섯 관점이 서로 강화하거나 충돌하는 지점은 무엇인가.
7. 어떤 조건이 현재 결론을 깨뜨리는가.

## 4. 목표 사용자와 핵심 작업

| 사용자 | 핵심 작업 | DartLab의 응답 |
|---|---|---|
| 개인 투자자 | 기업을 빠르게 이해하고 추가 조사 대상을 고름 | 대표 렌즈 결과, 핵심 동인, 근거, 위험 신호 |
| 분석가 | 결론의 원인과 반증 조건을 추적 | 상세 축, 시계열, 피어, 원문 근거, 가정 장부 |
| 개발자 | 분석 결과를 코드와 자동화에 사용 | 안정된 공개 호출, 구조화 결과, 상태 및 결손 계약 |
| AI agent | 질문에 맞는 분석과 근거를 조합 | 렌즈 선택, 작은 evidence bundle, 재현 가능한 결과 |
| 교육 사용자 | 재무, 산업, 거시의 연결을 학습 | 데이터에서 결론까지 단계별 설명과 드릴다운 |

## 6. 차별성

DartLab의 차별성은 단순히 기능 수나 축 수가 아니다.

1. DART와 EDGAR 원문 및 표에서 출발한다.
2. 회사별 비정형 공시를 비교 가능한 panel로 바꾼다.
3. 결론이 sourceRef, 기간, 가정, 결손 상태로 돌아간다.
4. 재무, 신용, 산업, 시장가격, 거시를 같은 기업과 시점 문맥에서 연결한다.
5. Python과 Terminal, Ask가 같은 분석 의미를 소비한다.

## 7. 비목표

- 기존 엔진 폴더를 한 패키지로 합치기
- 모든 내부 패키지를 동등한 공개 제품으로 홍보하기
- 새 범용 점수 하나로 다섯 렌즈를 평탄화하기
- 147개 축을 README의 첫 탐색 구조로 사용하기
- 렌즈 완성 전 Universe 범위를 추가 확장하기
- Story가 하위 엔진의 사실과 산식을 다시 구현하기
- Simulate가 근거 없는 예측이나 단일 목표값을 만들기
- 호환 계획 없이 기존 공개 호출을 즉시 변경하기

## 8. 성공 상태

이 계획은 다음 상태에서 성공으로 판정한다.

1. 다섯 렌즈 모두 축을 몰라도 대표 결과를 받을 수 있다.
2. 대표 결과에는 결론, 동인, 증거, 시점, 결손, 반증 조건이 있다.
3. Python, Terminal, Ask가 같은 결과 의미를 유지한다.
4. Story와 Simulate가 렌즈 결과를 재구현하지 않고 소비한다.
5. README 첫 화면에서 내부 레이어를 배우지 않아도 핵심 제품을 이해한다.
6. 활성 mainPlan이 네 개 상위 프로그램 아래에서 선후관계를 가진다.
7. 신규 축 수가 아니라 대표 워크플로 완료율과 반복 사용으로 제품 진척을 측정한다.
