# 05. E-panel : 모든 산출물에 기대를 붙이는 단일 메커니즘 (운영자 확정 설계, 2026-07-03)

## 0. 운영자 지시 원문 요지 (본 문서의 존재 이유)

1. "추정을 숫자 하나로 끝내지 말고 근거 있게 구조화해서 뽑아라." (매크로·크레딧 포함)
2. "IS/BS/CF 는 현재까지 시계열로 있다. **그 시계열에 추정치를 똑같이 붙이면 된다.**"
3. "모든 엔진의 모든 산출물에 기대가 붙는다면 그게 최고의 추정이다. 어떻게 할 것인가."
4. "최선의 방법, 어렵더라도 필요한 방법, 정공법."

## 1. 확정 원칙 (재토론 금지)

1. **산출물을 추정하지 않는다. 입력을 추정하고 엔진을 그대로 재통과시킨다.**
   산출물마다 예측기를 다는 순간 수천 개 잡동사니가 된다. 추정 대상 입력은 두 갈래뿐:
   ①회사 축 = E-3표(드라이버는 매출, 나머지는 역사 비율 전개 + 회계 항등식으로 닫음, `buildProforma` SSOT)
   ②거시 축 = 매크로 경로(BVAR fan SSOT). 이 둘을 넣고 엔진 재실행 = 모든 산출물의 E버전.
2. **통로는 panel 하나.** 모든 엔진이 wide 격자를 읽으므로, E-3표를 격자 형태(E기 컬럼:
   2026E·2027E·2028E)로 실적 뒤에 이어 붙이면 엔진 수정 0 으로 전 엔진이 미래를 계산한다.
   `asOf=과거`(과거 재생)의 미래 방향 대칭.
3. **실적 panel 불가침.** E기는 실적 SSOT(`dart/panel`)에 절대 쓰지 않는다. E-panel 은
   simulate(L2.5)가 실적 panel + proforma 원장을 조인해 만드는 **런타임 overlay view** 다.
   (계층 근거: 실적 panel=L1, proforma 원장=L2.5 산출이라 조인 주체는 L2.5 만 합법.)
4. **불확실성은 시나리오 경로로 전파.** 계정별 독립 분위 금지(매출 bear 인데 재고 bull 인
   세계는 없음). 일관 세계 3개(p25/p50/p75 매출 경로 → 전 계정 전개)를 통째로 민다.
   "만약" 토글 = 드라이버 경로 교체 후 재전개. **이것이 시뮬레이터의 정의 그 자체**
   (scenario-simulator 00 §5 드라이버→pro-forma→전 지표 전개와 동일 건물).
5. **엔진 개방은 게이트 순차.** 전 엔진 일괄 개방 금지. E-입력에 안전한(순수 panel 함수)
   엔진부터 하나씩 검증 개방. 1호 = credit(E-재무 → 추정 등급, 구조적 근거 동반).
   가격·시세 의존 엔진은 가격을 예측하지 않고 외생 가정 토글로 받는다.
6. **정직한 한계 명시.** 이 구조는 정확도를 올리지 않는다(정확도 상한 = 드라이버 질,
   성적표가 측정). 주는 것은 ①전 지표 커버리지 ②상호 일관성(모든 E가 한 가정 집합에서
   나와 모순 없음) ③반증 가능성(드라이버 봉인 + 결정론 전개 = 전 산출물 채점 가능).

## 2. 봉인 계약 (E-3표 구조화)

- 원장 세 번째 테이블 `expectations/proforma_{yyyy}.parquet`:
  `parentId(모체 매출 기대 행)·code·issuedAt·issuedLive·targetPeriod·quantile(25/50/75)·statement(IS/BS/CF)·account·value·bsBalanced`
- 계정 = ProFormaYear 전 필드 34개 (IS 11 · BS 17 · CF 6). 요약 3숫자(매출·영업이익·순이익)
  기대 행과 별개로, 전개 전체를 계정 단위로 남긴다.
- 원장은 드라이버+전개결과를 봉인하고, 재현은 결정론(leaf SSOT)이므로 계보(parentId)로 검증 가능.

## 3. 실행 순서 (E1~E4)

| 단계 | 내용 | 상태 |
|---|---|---|
| E1 | issueEarnings 가 proforma 전 계정 봉인 + HF 발행 + 테스트 | 🔨 |
| E2 | 터미널 재무제표 시계열에 E컬럼 병합(proforma 원장 직독) + 시나리오(분위) 표시 | ⏳ |
| E3 | `simulate/futurePanel`(가칭): 실적 series + E기 확장 overlay 조립 → credit 1호 E-재실행(추정 등급) 게이트 검증 | ⏳ |
| E4 | 표면 확산: E-지표를 갖는 패널들에 E컬럼 + 시나리오 토글, 개방 엔진 확대 | ⏳ |

## 4. 실패 기준 (05 한정)

1. E값이 실적 SSOT 에 섞여 저장되는 경로 발견 = 즉시 중단.
2. 계정별 독립 분위 전개(비일관 세계) 발견 = 즉시 수리.
3. 엔진에 E-전용 분기/특수케이스가 늘어나기 시작(덕지덕지 신호) = 설계 위반. 엔진은 무수정이 원칙.
