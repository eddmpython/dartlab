# 08. 회사 프로파일러 + 시나리오 연쇄 (8층 구조)

상태: v1.0 합의 (2026-07-05 운영자 메모 "시뮬레이터아이디어" + 토론. "프로파일 깊이 아주 깊게" 지시).
성격: 06 판독·sweep 의 상류(프로파일러)와 하류(연쇄·가시화)를 층 구조로 선언한다. 신설 엔진 0,
전부 `simulate/` 내부. 06 의 봉인·채점·전수 등재 규율을 층마다 상속한다.

## 1. 8층 구조 (운영자 메모 → 기존 자산 매핑)

| 층 | 내용 | 실체 |
|---|---|---|
| 1 | 데이터 호출 (엔진별 결과물) | table.py 상 차리기 (06 §7, 기존) |
| 2 | **회사 프로파일러** | **신규** profile.py (§2) |
| 3 | 경제 시나리오 판독 | issueMacro + 명명 프리셋 (라이브, 기존) |
| 4 | 경제→산업 시나리오 판독 | industry 엔진 + macroBeta (재료 기존, 배선 신규) |
| 5 | **회사 간 관계 시나리오 판독** | **신규** 관계 그래프 전파 (§3. 07 계열 lead-lag 와 동일 데이터) |
| 6 | 회사 시나리오 판독 | 06 판독 계약 + proforma (기존) |
| 7 | 가정별 시뮬레이션 결과 | sweep (기존) |
| 8 | 전 과정 가시화 | **DAG-as-data** (§4. 표현은 프론트 선택) |

층은 파이프가 아니다. **층마다 산출이 독립 판독으로 봉인·채점**되고(경제 판독은 이미 채점 중),
층간 연결(탄성·전파 계수)은 전부 가정 축(AssumptionLedgerRow)으로 선언되어 sweep 이 흔든다.
효과: 4층 연쇄의 오차 곱셈 대신 **약한 고리가 측정으로 특정**된다. 조건부 층(3~6 연쇄분)은
06 §5 레짐 조건부 채점 규율(실현 조건만 채점 + airtime 분모) 아래 있다.

## 2. 회사 프로파일러 (깊이 = 전수)

**정체성**: 프로파일은 예측이 아니라 **상태**다. 봉인·채점 대상이 아니라 PIT 버전드 사실
(형질마다 rcept_dt·provenance·staleness age)이고, 검증은 재현성(같은 asOf 재계산 = byte 일치)과
출처로 한다. 06 §5c 가드 2종(replay 항등성·look-ahead 카나리아) 상속.

**깊이 원칙 (운영자 지시 "아주 깊게" = 전수)**: 형질 등재는 손 선별이 아니라 카탈로그 전수다.
extractionCatalog 88개념 + frame/inventory 전 단위 열거 + allFilings 이벤트 이력 + gather/quant
파생가 뽑을 수 있는 **모든** 형질을 등재하고, 어떤 형질이 예측에 기여하는지는 성적표
(표면 x 형질 셀, §5)가 도태시킨다. 죽은 형질도 목록에서 안 사라진다 (06 §3 동형).

**형질의 8개 축 (전수 등재의 분류 골격, 고정 목록 아님)**:

1. 사업 구조: 세그먼트 매출/이익 구성·지역별 매출·주요 제품·수주잔고·원재료 (extractionCatalog)
2. 관계 그래프: 계열/지분 엣지(사업보고서·대량보유)·대주주·공급계약 상대방(단일판매공시)·
   주요 고객 의존도·밸류체인 위치(1차/2차 공정)
3. 자본·자금조달 형질: CB/BW 발행 이력·리픽싱 조항/횟수·유상증자 이력·부채 만기 구조·담보
4. 거버넌스 형질: 최대주주 변경 빈도·임원 매매 패턴·불성실공시 누적 벌점·감사 지연 이력·
   횡령배임 이력
5. 노출 벡터: macroBeta(금리·환율·유가)·수출 비중·고객 집중도
6. 시장 미시 형질: 유동성·유효 스프레드·시총·회전율·MAX 성향·개인 비중 proxy
7. 노동·설비: 직원 수 추이·capex 패턴·생산능력 (extractionCatalog workforce/segment)
8. 서사 형질: 리스크 문단 변화·신사업 키워드 (frame/narrative)

**계약**: `simulate/profile.py`, `profile(code, asOf)` → 형질 dict + 관계 엣지 목록. 원천은
공개 verb 만 (엔진 로직 재구현 금지). KR/US 대칭 (US: Form 4 패턴·NT 지연·SFAS 131 고객 엣지,
07 §1b 매핑).

**실측 근거 (2026-07-05, `profilerTraitSplit.py`)**: 형질 조건부가 실제로 판독을 가른다.
유상증자결정(n=5,135) D+10 초과: CB 발행 이력 0회 **-2.0%** vs 이력 있음 **-2.9~-3.6%** (~1.5배).
전환청구권행사는 분할 약함(-5.0 vs -5.6) = 형질이 모든 표면을 가르는 게 아니라 어떤 표면을
가르는지도 측정이 정한다는 규율의 대조군. 부수 발견: 타입 정규화가 "주요사항보고서(하위타입)"
괄호를 절단해 하위타입을 뭉갬 → **surfaces.py 정규화 규칙에 래퍼 보고서 괄호 내 하위타입 추출
필수** (원문 매칭 시 유상증자결정 894→5,135건).

## 3. 관계 전파 층 (5층)

- 그래프 = 프로파일러 축 2 의 엣지 (계열·지분·공급·고객). 전파 = "먼저 움직인 노드(대형 실적·
  충격) → 엣지 가중 x 탄성 → 추종 노드 판독". 탄성은 가정 축 (사전 선언·sweep 대상).
- 07 §1 레버 11(계열 lead-lag, 미공표 영역)과 같은 데이터·같은 실측이 이 층의 bootstrap.
- 채점: 전파 판독도 일반 판독과 동일 봉인·채점 (표면 id = "cascade.groupLeadLag" 류).

## 4. 가시화 계약 (8층): DAG-as-data

- 시뮬레이터가 연쇄 자체를 산출물로 낸다: 노드 = 각 층 판독(refs·성적표 인용 포함), 엣지 =
  전파 채널(탄성 값 + 가정 id + provenance). JSON, 주간 블록에 봉인 (06 §7b 해시체인 포함).
- 프론트는 fetch 작업대로 이 JSON 을 소비해 트리·산키·그래프·3D 무엇으로든 렌더 (표현 교체가
  데이터 계약을 못 건드림). UI 구현은 별도 사이클 (공개 터미널 무중단 규약).

## 5. 형질 조건부 성적표 (프로파일러의 예측 기여 측정)

- 06 §4 성적표 차원에 형질 축 추가: 표면 x 시장 x **형질 버킷** x 레짐 x 지평.
- 형질 기여 판정도 06 §4 깔때기 그대로 (주단위 t → FDR → 셀 표본 게이트 미달 "미검증").
- 형질 수백 개 x 표면 수백 개 = 셀 폭발 주의: 셀 신설은 자동이되 주장 승격은 깔때기만.
